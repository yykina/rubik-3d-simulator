# 求解器设计笔记（重要，勿丢）

## 问题本质

Kociemba 的坐标（twist / flip / slice / cp / ep / sp）**不能唯一决定魔方的物理姿态**：
角块朝向值只说明「U/D 贴纸指向哪个轴」，不包含绕该轴旋转的切向自由度（gauge）。
因此 `coordinate → state` 没有唯一解，任何「从坐标造一个规范状态再推进坐标」的做法
都会在若干步后与真实状态分叉（已实测：规范姿态方案 300 步中约 298 步发散）。

## 正确做法（单遍 BFS，同时建「坐标 → 代表状态」与坐标转移）

```
frontier = [(key(初始状态), 真实状态)]      # 每个未访问坐标只保留一个代表状态
dist[key] = 0
循环直到 frontier 为空:
    next = []
    for (key, rep) in frontier:
        for m in moves:
            st = applyPack(clone(rep), m)
            k2 = key(st)
            if dist[k2] == 未访问:          # 该坐标第一次被到达 → 这个 st 就是它的代表
                dist[k2] = depth + 1
                trans[key][m] = k2          # 记录坐标转移（代表状态推出的，必然自洽）
                next.push((k2, st))
    frontier = next
```

要点：
- `trans` 只在坐标**第一次**被访问时记录，因此所有转移都来自同一个代表状态，
  与搜索时的启发函数天然一致（不会出现「表和状态不一致」）。
- 代表状态只存在于当前层，内存是 O(层宽)，不是 O(状态空间)。
- 上一版 75 秒的原因是把**完整几何状态**（26 个 3×3 矩阵）当状态对象反复 slice；
  本方案用紧凑朝向编码（带符号置换矩阵，6 bit/块）+ 数组复制，速度可接受。

## 状态表示

- `perm[26]`：`perm[slot] = cubie 编号`
- `ori[26]`：朝向编码（6 bit：低 3 位 = 局部第 c 个基向量映射到的世界轴，第 3 位 = 符号）
- 组合规则与 `applyTurn` 完全同构：`ori[to] = compose(turnCode, ori[from])`

## 搜索

IDA*，但**直接携带真实状态**（每层 clone），启发值取坐标剪枝表。
因为搜索不像 BFS 那样只走「第一次到达」的路径，不能用坐标转移表推进状态，
所以必须在状态上走；深度上限 12（阶段一）/ 18（阶段二）时节点数可接受。

## 历史踩坑记录（都已修复，勿回退）

1. `applyTurn` / `applyPack` 必须「先收集赋值再统一写入」，否则就地置换读到被覆盖的源位置。
2. 转动角度：U=绕 +y −90°、D=绕 +y +90°、R=绕 +x +90°、L=绕 +x +90°、
   F=绕 +z +90°、B=绕 +z +90°（标准记号，已用 (R U R' U')×6 与 U 的角块置换校验）。
3. `frameOf` 的列组合必须是 `col0 = d×v, col1 = v, col2 = −d`，否则 det = −1（镜像），
   朝向会算错。
4. `readCornerPerm` 语义是 `cp[piece] = slot`；建表用的 `stateFrom*Perm` 必须用同一语义。
5. 朝向值语义：角块 0→U/D 面、1→+x 面、2→+z 面；棱块 0→U/D 面、1→侧面。

## 2026-09-30 复审：当前实现为何不可靠（务必先读）

在用**独立面片校验**（`misplacedStickers`：每面 9 张贴纸是否同色）复核后，确认：
两阶段解在随机 25 步打乱中约 **1/5** 会在外观上仍是错的——棱块位置对、贴纸颜色错
（典型：FL 与 FR 的贴纸互换）。旧的 `isSolved()` 跳过了 E 层棱块朝向，所以一直误判为成功。

### 根因

1. 阶段一的 `flip` 坐标是**按槽位**定义的（「该槽位的 U/D 贴纸是否朝上下」）。
   对 E 层棱块，它**无法约束棱块的完整朝向**：一个「贴纸原地互换」的状态照样读出 `flip === 0`。
2. 于是阶段一可能停在「坐标上是 G1、物理上贴纸错位」的状态；
   而阶段二的动作（如 L2）又会改变 E 层棱块朝向，最终无法收敛到外观还原。
3. 曾尝试把 `flip` 改成带物理约束的版本（E 层棱块的 U/D 贴纸必须指向该槽位的层轴），
   该定义经 3000 例随机状态验证与物理朝向完全一致，**但它改变了 G1 的定义**，
   使得阶段一的上界 12 不再够用（实测 bound 12 需 ~54 秒），因此暂时回退。

### 结论与建议路径

- 现状：`solve()` 会对候选解做独立面片校验，**校验不过就抛错**，绝不返回错解；
  界面已据此停用自动求解按钮。
- 修复建议（二选一，都需要重建剪枝表并升 `CBxx`）：
  - **A**：采用物理约束版 `flip`，并重建阶段一距离表（该表的 BFS 要用真实可达状态，
    不能从坐标反推合成状态——合成的朝向不合法，正是历史踩坑点）。
  - **B**：接入成熟实现（如 min2phase 的独立版本），用本项目几何做输入/输出适配，
    并以 `tools/verify-solver-core.js` 作为验收门槛。
- **验收门槛**：`node tools/verify-solver-core.js` 必须达到 100% 通过
  （独立面片校验 0 错位），才允许在界面上重新启用求解按钮。

## 2026-09-30（续）迁移开源方案 min2phase 的进展与卡点

按审查建议，已把成熟的 **min2phase**（MIT，cs0x7f）自包含的低层求解器移植到
`vendor/min2phase.port.js`（只依赖 `{cp,co,ep,eo}` 四组数组，不依赖 kpuzzle/alg）。

### 已完成
- 移植后可正常运行，**并修复了移植过程中引入的 4 个 bug**：
  1. `EPermR2S` 的填充循环漏了一行赋值（`EPermR2S[idx2] = count << 4 | s`），
     导致所有棱块置换的对称索引都退化为 0，`MEPermPrun` 只能扩展 1 个状态、BFS 永不收敛；
  2. `depth` / `done` 未在每个剪枝表 BFS 前复位；
  3. 局部变量 `twist0/flip0` 与模块级常量数组 `twist/flip` 同名（`const` 赋值报错）；
  4. 若干 `const sym` 在循环里被 `>>=` 修改。
- 修复后 **初始化 400~550 ms**、单次求解 **~3 ms**，剪枝表全部填满
  （`MEPermPrun`/`MCPermPrun` 均 `done = 66432`）。

### 当前卡点：朝向约定未对齐
- 已确认的差异：**置换互为逆排列** —— 本项目 `cp[piece] = slot`，
  min2phase 是 `cp[slot] = piece`（已用 min2phase 自己的 `moveCube` 对 R 做过验证）。
- **朝向仍对不上**：以 min2phase 自己的 `moveCube[3]`（R）为基准，
  它给出 `eo = 全 0`，而本项目的 `eo` 给出 4 个 1；F/B 两个动作两边一致，R/L 不一致。
  推测 min2phase 的 EO 采用的是「把该块送回原位后，U/D 贴纸是否仍指向原位轴」这一定义，
  但按此实现的候选规则与它的 `co`/`eo` 仍不能逐项对齐（已尝试参数化规则穷举与多种重排）。

### 下一步（任一即可收敛）
1. 用 min2phase 自身当「神谕」：从还原态出发按它的 `moveCube` 做 BFS，
   对每个 (块, 槽位, 朝向) 记录它的 `eo`/`co` 取值，直接建一张换算表，
   再用 `tools/verify-solver-core.js` 做验收（必须 100% 通过）。
2. 或换用其它实现（如 `cube-solver` / `kociemba` 的 wasm 版本），
   以「回放后 `misplacedStickers() === 0`」为唯一验收标准。
3. 自研路线：采用物理约束版 `flip`，并按本文档开头「单遍 BFS、坐标→代表状态」的正确算法
   重建阶段一距离表。

**验收门槛（务必遵守）**：`node tools/verify-solver-core.js` 全绿之前，
不要在界面上重新启用「提示 / 自动求解」。
